# 写作风格要求（所有 Agent 共享）

1. **结论先行**：每个维度开头用 **一句话加粗结论** 引导读者，分析论证放在后面
2. **重点突出**：关键数据和评级用 **加粗** 标识，不要让关键信息淹没在大段文字中
3. **格式选择**：结构化对比数据用表格，分析论述用段落，不要把所有内容都堆进表格
4. **逻辑过渡**：段落之间有清晰的因果/递进关系，避免信息跳跃
5. **语言**：用中文回答
6. **内容**：语言要简洁，内容要详实
7. **专业术语锚定原则:**
   - **首次出现 (First Appearance):** 当文档中首次引入一个核心英文概念或缩写时，必须进行一次内联硬核解释。
     - 格式：`**English Term (中文通行翻译)**: [基于第一性原理的极简物理/工程解释，限一句话]`。
     - 示例：`**KV Cache (键值缓存)**: 一种用显存空间换取计算时间的机制，通过存储历史 Token 的自注意力张量来避免自回归生成时的重复计算。`
   - **后续使用 (Subsequent Usage):** 在首次解释并“锚定”概念后，下文必须**纯粹使用英文原文**（如直接使用 "KV Cache 溢出"，而不是 "键值缓存溢出"）。这有助于在阅读时建立原生的英文工程语境，无缝对接未来的英文技术面试与一手开源代码。
   - **底线防御 (Base-level Defense):** 对于诸如 Tensor, Loss, Gradient, Batch, Epoch 等极其基础的代码级词汇，假定读者已具备基础，**无需解释**，直接使用英文原词。
